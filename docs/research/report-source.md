# PRISM 图像粒子市场调研：内部研究底稿

- 受众：PRISM 产品与开发决策
- 日期：2026-09-06
- 范围：浏览器端图片粒子工具、开源编辑器、通用粒子框架与渲染技术
- 假设：首版仍为无需账户的本地单页工具；不讨论传统影视级桌面粒子软件

## 直接答案

PRISM 不应通过增加更多同时可见的参数与同类竞争。公开样本共同证明，图片上传、密度/速度/颜色控制、鼠标互动已经是基础能力；预设、导出、移动手势、自动图像适配与性能回退才组成实用的创作闭环。PRISM 的可守差异是 2.5D 空间观看、克制的作品界面、图片间连续重组和“捕捉瞬间”的导出仪式。

## 证据与推断

- ParticleFX 公布了 20+ 参数、4 个预设、自定义本地预设、光标物理、涟漪和嵌入代码导出，证明全参数编辑器路线已存在成熟开源样本。
- Particular Drift 公布 Sobel 边缘、Perlin/Simplex 流场、图片/视频导出和本地处理，说明流场与输出闭环都有可行的浏览器实现。
- Trickle 模板提供上传、密度、颜色、速度、行为和复位，说明这些能力已商品化为模板基础项。
- tsParticles 暴露形状、交互、轨迹、声音、缩放、mask 等大量配置，适合开发框架，而不适合直接成为 PRISM 的产品信息架构。
- Three.js 官方粒子示例已覆盖 sprites、动态点、波面、自定义属性与 compute 粒子，因此算法名称本身不足以形成品牌识别。
- MDN 将 WebGPU 标为非 Baseline；Three.js WebGPURenderer 提供 WebGL2 回退。由此推断近期应渐进增强，而不是整体迁移。

## 主要限制

- 无可验证的同类产品用户规模和转化率，不能判断哪一项功能直接提升留存。
- Particleify 页面访问超时，仅用官方搜索摘要做低置信度功能映射。
- 产品优先级是依据功能频次、PRISM 当前能力和实现成本做出的推断，仍需以后续使用数据验证。

## 搜索范围与停止理由

检索了 image-to-particle web app、Three.js particle image、粒子导出、流场编辑器、tsParticles mask、Three.js/WebGPU 官方文档。关键产品路线与技术限制已有一手仓库或官方文档支撑；继续添加相似演示项目不会改变“输出闭环 + 预设 + 自动适配优先”的结论，因此停止广泛检索。
