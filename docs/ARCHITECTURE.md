# PRISM 架构说明

## 运行链路

```text
图片文件 / 粘贴板 / 拖放
  → 浏览器解码
  → Canvas 缩采样
  → 透明度、边缘背景、亮度与边缘强度分析
  → BufferGeometry 顶点属性
  → 单个 THREE.Points + ShaderMaterial
  → RenderPass → UnrealBloomPass
  → 屏幕 / 2× PNG
```

## 粒子数据

每个可见像素生成一个粒子，并写入八组属性：目标位置、球面起点、散开方向、RGB、亮度、随机因子、边缘强度和透明度。三种形态共用一个 shader，以 `uModes` 向量连续混合，避免切材质和硬跳变。

## 图像适配

采样先计算边缘带亮度，对深背景建立阈值；主体过少时回退到完整可见像素。构建完成后计算可见粒子包围盒并重新居中，镜头再结合 Canvas 宽高比拟合，所以透明边距、横图和竖图使用同一套逻辑。

## 状态与交互

状态目前保留在 `app.js` 的模块作用域：形态和参数映射到 shader uniform；旋转与镜头使用目标值并在渲染循环内阻尼收敛；定格、参数面板、气质和质量属于 UI 状态。localStorage 只保存自定义气质、最后气质和质量选择。

Pointer Events 同时服务鼠标与触控。一个指针控制旋转，两个指针记录起始距离并按比例更新镜头。键盘只在非表单控件上应用全局快捷键，隐藏面板使用 `inert` 退出 Tab 顺序。

## 自适应质量

| 档位 | 桌面粒子预算 | 移动粒子预算 | 桌面 DPR 上限 | 移动 DPR 上限 |
| --- | ---: | ---: | ---: | ---: |
| 轻盈 | 8,500 | 8,500 | 1.0 | 0.9 |
| 均衡 | 23,500 | 14,500 | 1.6 | 1.25 |
| 精致 | 42,000 | 24,000 | 2.0 | 1.45 |

自动模式从均衡开始，以 120 帧为窗口。持续低于目标才降级，连续四个高帧率窗口才恢复，避免临界设备反复切换。

## 导出

定格模式让 Canvas 获得完整视口。PNG 导出临时把 renderer 与 composer 提升到最多 2×、最长边 4096px；`toBlob` 完成后恢复像素比、尺寸和镜头。失败路径也执行恢复。

## 当前边界

- `app.js` 已超过适合单文件维护的体量；V1.1 会按 image、renderer、interaction、persistence、UI 拆分。
- 采样仍运行在主线程；大图 Worker 化列入路线。
- WebGPU 只作为未来增强通道，当前稳定基线为 WebGL。
- `dist/` 当前纳入版本控制，便于直接静态托管；每次提交前必须由当前源码重新构建。
